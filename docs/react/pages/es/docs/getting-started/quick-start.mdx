Esta guía te lleva de cero a un QR de pago funcional en menos de cinco minutos.

## 1. Crear una solicitud de pago en tu backend

Tu servidor llama a `pointOfSale.createPaymentRequest()` del SDK de Fluxis y devuelve el token NASPIP al navegador. **Nunca generes tokens de pago en el cliente.**

## 2. Renderizar el código QR

Pasa el token a `FluxisQrCode` dentro de un `FluxisProvider`:

```tsx
import { FluxisProvider, FluxisQrCode, CompatibleApps } from '@fluxisus/react';

export function CheckoutPage({ token }: { token: string }) {
  return (
    <FluxisProvider theme={{ colorPrimary: '#2563eb' }}>
      <FluxisQrCode token={token} size={280} />
      <CompatibleApps token={token} />
    </FluxisProvider>
  );
}
```

`FluxisProvider` es opcional — los componentes funcionan sin él usando los valores de tema predeterminados. Envuélvelo una vez al nivel del layout para que el tema se propague a todos los componentes Fluxis.

## 3. Monitorear el estado del pago

Una vez mostrado el QR, usa `usePaymentStatus` para detectar cuando llega el pago:

```tsx
import { usePaymentStatus } from '@fluxisus/react';

function PaymentStatus({ paymentRequestId }: { paymentRequestId: string }) {
  const { status, isPolling } = usePaymentStatus(`/api/payment-status/${paymentRequestId}`);

  if (status === 'completed') return <p>¡Pago recibido!</p>;
  if (status === 'expired') return <p>QR expirado — por favor recarga la página.</p>;

  return <p>{isPolling ? 'Esperando pago…' : status ?? 'Cargando…'}</p>;
}
```

El hook consulta tu ruta backend cada 5 segundos y se detiene automáticamente en cualquier estado terminal (`completed`, `expired`, `failed`, `overpaid`, `underpaid`). Consulta [Backend del Comerciante](/es/docs/guides/merchant-backend) para implementar la ruta necesaria.
