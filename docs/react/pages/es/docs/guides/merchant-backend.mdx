title: Backend del Comerciante
---

`usePaymentStatus` consulta **tu** backend, no la API de Fluxis. Esto mantiene tus credenciales de API en el servidor y te da control total sobre qué datos llegan al navegador.

Necesitas implementar una ruta simple que el hook pueda consultar.

## Ruta requerida

El hook llama a `GET <statusUrl>` en un intervalo y lee el campo `status` de la respuesta JSON. Cualquier estructura JSON con un `"status"` de tipo string en el nivel superior funciona.

```
GET /api/payment-status/:id
→ { "status": "processing", ... }
```

## CORS para frontends en origen cruzado

Si tu frontend y backend están en orígenes distintos (p. ej. `app.example.com` llamando a `api.example.com`), necesitas las cabeceras CORS estándar:

```
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Methods: GET
```

### Exponer la cabecera Date (corrección de sesgo de reloj)

`usePaymentStatus` lee la cabecera de respuesta `Date` para calcular un offset de reloj servidor/cliente usado por los conteos regresivos de expiración. `Date` no está en la lista segura CORS del navegador, por lo que debes exponerla explícitamente para solicitudes en origen cruzado:

```
Access-Control-Expose-Headers: Date
```

Sin esta cabecera el offset permanece en `0` — nada falla, pero los temporizadores de expiración no tendrán corrección de sesgo.

## Notas de seguridad

- Nunca devuelvas tu `api_secret` ni tokens de autenticación en la respuesta.
- `getPaymentRequest` devuelve solo el estado y los metadatos del pago — es seguro reenviarlo tal cual.
- Agrega autenticación a la ruta si es necesario (p. ej. verifica que el usuario autenticado sea propietario de la solicitud de pago).
- Aplica limitación de tasa a la ruta si te preocupa el polling excesivo. El intervalo de polling predeterminado del SDK es de 5 segundos.

## Estados devueltos

| Estado | Significado | Polling |
|--------|-------------|---------|
| `pending` | Creado, esperando selección de moneda | continúa |
| `created` | Moneda seleccionada, dirección asignada | continúa |
| `processing` | Depósito detectado, confirmando | continúa |
| `completed` | Pagado completamente | **se detiene** |
| `confirmed` | Transacción confirmada | continúa |
| `expired` | Token expirado, sin pago | **se detiene** |
| `failed` | Fallo en el procesamiento | **se detiene** |
| `overpaid` | Se recibió más de lo solicitado | **se detiene** |
| `underpaid` | Se recibió menos de lo solicitado | **se detiene** |
