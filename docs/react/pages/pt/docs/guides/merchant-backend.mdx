`usePaymentStatus` consulta **seu** backend, não a API da Fluxis. Isso mantém suas credenciais de API no servidor e dá a você controle total sobre quais dados chegam ao navegador.

Você precisa implementar uma rota simples que o hook possa consultar.

## Rota necessária

O hook chama `GET <statusUrl>` em um intervalo e lê o campo `status` da resposta JSON. Qualquer estrutura JSON com um `"status"` do tipo string no nível superior funciona.

```
GET /api/payment-status/:id
→ { "status": "processing", ... }
```

## CORS para frontends em origem cruzada

Se seu frontend e backend estão em origens diferentes (ex.: `app.example.com` chamando `api.example.com`), você precisa dos cabeçalhos CORS padrão:

```
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Methods: GET
```

### Expor o cabeçalho Date (correção de desvio de relógio)

`usePaymentStatus` lê o cabeçalho de resposta `Date` para calcular um offset de relógio servidor/cliente usado em contagens regressivas de expiração. `Date` não está na lista segura CORS do navegador, então você deve expô-lo explicitamente para requisições de origem cruzada:

```
Access-Control-Expose-Headers: Date
```

Sem esse cabeçalho, o offset permanece em `0` — nada quebra, mas os temporizadores de expiração não terão correção de desvio.

## Notas de segurança

- Nunca retorne seu `api_secret` nem tokens de autenticação na resposta.
- `getPaymentRequest` retorna apenas o status e os metadados do pagamento — é seguro encaminhá-lo como está.
- Adicione autenticação à rota se necessário (ex.: verifique que o usuário autenticado é proprietário da solicitação de pagamento).
- Aplique limitação de taxa à rota se estiver preocupado com polling excessivo. O intervalo de polling padrão do SDK é de 5 segundos.

## Status retornados

| Status | Significado | Polling |
|--------|-------------|---------|
| `pending` | Criado, aguardando seleção de moeda | continua |
| `created` | Moeda selecionada, endereço atribuído | continua |
| `processing` | Depósito detectado, confirmando | continua |
| `completed` | Totalmente pago | **para** |
| `confirmed` | Transação confirmada | continua |
| `expired` | Token expirado, sem pagamento | **para** |
| `failed` | Falha no processamento | **para** |
| `overpaid` | Recebido mais do que solicitado | **para** |
| `underpaid` | Recebido menos do que solicitado | **para** |
