title: Merchant Backend

`usePaymentStatus` polls **your** backend, not the Fluxis API. This keeps your API credentials server-side and gives you full control over what data reaches the browser.

You need to implement one thin route that the hook can poll.

## Required route

The hook calls `GET <statusUrl>` on an interval and reads the `status` field from the JSON response. Any JSON shape with a top-level `"status"` string works.

```
GET /api/payment-status/:id
→ { "status": "processing", ... }
```

## CORS for cross-origin frontends

If your frontend and backend are on different origins (e.g. `app.example.com` calling `api.example.com`), you need standard CORS headers:

```
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Methods: GET
```

### Exposing the Date header (clock-skew correction)

`usePaymentStatus` reads the `Date` response header to compute a server/client clock offset used by expiration countdowns. `Date` is not in the browser's CORS safelist, so you must expose it explicitly for cross-origin requests:

```
Access-Control-Expose-Headers: Date
```

Without this header the offset stays `0` — nothing breaks, but expiration timers won't be skew-corrected.

## Security notes

- Never return your `api_secret` or auth tokens in the response.
- `getPaymentRequest` returns only the payment status and metadata — it's safe to forward as-is.
- Add authentication to the route if needed (e.g. check the logged-in user owns the payment request).
- Rate-limit the route if you're concerned about excessive polling. The SDK's default poll interval is 5 seconds.

## Statuses returned

| Status | Meaning | Polling |
|--------|---------|---------|
| `pending` | Created, awaiting currency selection | continues |
| `created` | Currency selected, address assigned | continues |
| `processing` | Deposit detected, confirming | continues |
| `completed` | Fully paid | **stops** |
| `confirmed` | Transaction confirmed | continues |
| `expired` | Token expired, no payment | **stops** |
| `failed` | Processing failed | **stops** |
| `overpaid` | Received more than requested | **stops** |
| `underpaid` | Received less than requested | **stops** |
