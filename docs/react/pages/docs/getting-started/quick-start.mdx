This guide walks you from zero to a working payment QR in under five minutes.

## 1. Create a payment request on your backend

Your server calls `pointOfSale.createPaymentRequest()` from the Fluxis SDK and returns the NASPIP token to the browser. **Never generate payment tokens client-side.**

## 2. Render the QR code

Pass the token to `FluxisQrCode` inside a `FluxisProvider`:

```tsx
import { FluxisProvider, FluxisQrCode, CompatibleApps } from '@fluxisus/react';

export function CheckoutPage({ token }: { token: string }) {
  return (
    <FluxisProvider theme={{ colorPrimary: '#2563eb' }}>
      <FluxisQrCode token={token} size={280} />
      <CompatibleApps token={token} />
    </FluxisProvider>
  );
}
```

`FluxisProvider` is optional — components work without it, falling back to default theme values. Wrap it once at the layout level so the theme propagates to all Fluxis components.

## 3. Poll for payment status

Once the QR is shown, use `usePaymentStatus` to watch for the payment landing:

```tsx
import { usePaymentStatus } from '@fluxisus/react';

function PaymentStatus({ paymentRequestId }: { paymentRequestId: string }) {
  const { status, isPolling } = usePaymentStatus(`/api/payment-status/${paymentRequestId}`);

  if (status === 'completed') return <p>Payment received!</p>;
  if (status === 'expired') return <p>QR expired — please refresh.</p>;

  return <p>{isPolling ? 'Waiting for payment…' : status ?? 'Loading…'}</p>;
}
```

The hook polls your backend route every 5 seconds and stops automatically on any terminal status (`completed`, `expired`, `failed`, `overpaid`, `underpaid`). See [Merchant Backend](/docs/guides/merchant-backend) for the backend route you need to implement.
