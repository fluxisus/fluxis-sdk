## ADDED Requirements

### Requirement: Single normative protocol document
The Fluxis BLE Handoff Protocol SHALL be specified in `docs/ble-protocol.md`, version 3, and every BLE SDK SHALL implement that document. Version bytes `0x01` and `0x02` are reserved and SHALL be rejected.

#### Scenario: Prototype record is rejected
- **WHEN** a payer reads a RECORD whose first byte is `0x02`
- **THEN** decoding fails with `unsupported_version` and the collector is not offered as a candidate

### Requirement: Amounts in minor units with explicit scale and currency
The discovery record SHALL encode an optional amount as an unsigned 64-bit count of minor units (at most 2^63−1), a scale from 0 to 18, and a currency code of 0–12 characters from `[A-Z0-9]`.

#### Scenario: Two-decimal fiat amount
- **WHEN** a collector starts with amount `12.50` and currency `ARS`
- **THEN** the record carries `minorUnits = 1250`, `scale = 2`, `currency = "ARS"`, and payers format it as `ARS 12.50`

#### Scenario: Open-amount session
- **WHEN** a collector starts without an amount
- **THEN** the record's `AMOUNT_PRESENT` flag is clear and no amount fields are encoded

### Requirement: Token confidentiality against passive eavesdroppers
The collector SHALL encrypt the NASPIP token with AES-256-GCM under a key derived by HKDF-SHA256 from an ephemeral P-256 ECDH secret, salted with the transcript hash of the exact RECORD and START bytes. No secret SHALL be readable from the RECORD.

#### Scenario: Recorded exchange reveals nothing
- **WHEN** an observer captures the RECORD, START, DATA and ACK of a session
- **THEN** the observer cannot derive the data key without one of the two ephemeral private keys

#### Scenario: Tampered ciphertext
- **WHEN** a DATA payload is modified in transit
- **THEN** the payer's AEAD check fails, the payer writes ABORT `decrypt_failed`, and no token is returned

### Requirement: Bounded framing
Messages SHALL be split into frames of `type | seq | total | payload` that fit one ATT value (`MTU − 3`), with at most 255 frames and 4096 bytes per message, and receivers SHALL reject out-of-order, interleaved, inconsistent or oversized frame sequences.

#### Scenario: Default MTU
- **WHEN** the negotiated MTU is 23
- **THEN** each frame payload is at most 17 bytes and a 4067-byte token still fits in one DATA message

### Requirement: Shared conformance vectors
`packages/ble/test-vectors/vectors.json` SHALL be generated by the reference implementation, and every SDK SHALL run all of it in CI, including exact error strings.

#### Scenario: Stale vectors
- **WHEN** the reference implementation changes without regenerating `vectors.json`
- **THEN** `generate_vectors.py --check` fails in CI
