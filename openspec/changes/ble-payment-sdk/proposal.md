## Why

Fluxis points of sale hand the NASPIP token to the customer as a QR code. A BLE handoff lets a
nearby wallet receive the same token without scanning. A prototype exists between TeroKiosk
and an internal Fluxis iOS build, but it lives in app code, can't be reused by other POS or
wallet integrators, and has protocol weaknesses: the key material is readable from the
discovery record, amounts are whole pesos with no currency, and the framing rules are
ambiguous. The owner confirmed that backward compatibility with the prototype isn't required.
TeroKiosk and the Fluxis app will migrate to the SDK.

## Revision (2026-10-20): preview only

The owner replaced the claim handshake with a public, read-only preview: nobody can take the
POS, every nearby wallet can read the active sale (the NASPIP token, or the POS id when the
token doesn't fit), and whoever pays through the API is the payer. The ECDH/AES-GCM delivery,
framing, BUSY and the delivered/expired states were removed. Because nothing was released, the
change stays protocol version 3. The original text below is kept as history; the specs in
this change and `docs/ble-protocol.md` describe the current design.

## What Changes

- New normative spec `docs/ble-protocol.md`: Fluxis BLE Handoff Protocol **v3**. It defines
  one fixed GATT service, a strict discovery record with amounts in minor units plus an
  explicit scale and currency, ephemeral P-256 ECDH with an HKDF key schedule bound to a
  transcript hash, AES-256-GCM delivery, an HMAC ACK, framing rules, the collector state
  machine and timeouts.
- New shared conformance vectors `packages/ble/test-vectors/vectors.json`, generated by a
  Python reference implementation and checked in CI.
- New Kotlin SDK `packages/ble/kotlin`: `fluxis-ble-core` (pure JVM) and `fluxis-ble-android`
  (minSdk 26: `FluxisBleCollector`, `FluxisBlePayer`, `FluxisBlePermissions`).
- New Swift SDK `packages/ble/swift`: `FluxisBLECore` (CryptoKit/swift-crypto) and `FluxisBLE`
  (CoreBluetooth `FluxisBLEPayer`, plus an iOS collector scaffold).
- CI workflows for both SDKs, release-please components `ble-kotlin` and `ble-swift`, and
  publish jobs (GitHub Packages, plus a public SPM mirror repository).
- **BREAKING** relative to the prototype: v3 doesn't interoperate with discovery record v2 or
  bootstrap v1, and receivers reject version bytes 1 and 2.

## Capabilities

### New Capabilities
- `ble-handoff-protocol`: wire format, cryptography, framing, timeouts and conformance vectors.
- `ble-collector`: POS role: advertise, serve the record, deliver the token, re-arm, expire.
- `ble-payer`: wallet role: discover, claim, and return the token with typed errors.

### Modified Capabilities
(none)

## Impact

- New packages under `packages/ble/`. The existing backend and frontend SDKs are untouched.
- Repo-level config only: `release-please-config.json`, `.release-please-manifest.json`,
  `.github/workflows/release-please.yml`, two new workflows, `Makefile`, `README.md`,
  `CLAUDE.md`, `llms.txt`.
- New secret for the Swift mirror: `BLE_SWIFT_MIRROR_TOKEN` (push access to
  `fluxisus/fluxis-ble-swift`, which must be created).
- Consumers: TeroKiosk / Clover Android app (collector), Fluxis Android and iOS wallets (payer).
